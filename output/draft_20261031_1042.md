# Designing Ultra-Low-Power LoRaWAN Nodes with the Dual-Core STM32WL55JC

Battery-powered IoT deployments demand an aggressive balance between radio link budget, computation performance, and sleep-state leakage current. While discrete two-chip solutions (an MCU plus a standalone sub-GHz transceiver like the SX126x) have long been the industry standard, STMicroelectronics’ **STM32WL55JC** fundamentally reshapes the architecture. 

By integrating an Arm Cortex-M4 (application processor), an Arm Cortex-M0+ (dedicated radio network processor), and a multi-modulation sub-GHz radio onto a single monolithic die, the STM32WL55JC provides hardware-enforced isolation, sub-microamp standby currents, and an optimized RF BOM.

Here is a practical guide to architecting an ultra-low-power LoRaWAN endpoint using this dual-core powerhouse.

---

## 1. Dual-Core Architecture: Separation of Concerns

A primary operational failure in long-lifecycle IoT nodes is firmware corruption or priority inversion caused by running user application logic, sensor polling, and time-critical LoRaWAN MAC layers on a single execution thread. 

The STM32WL55 addresses this with asymmetric multiprocessing (AMP):

*   **Cortex-M0+ (Network Processor / Secure Core):** Executes the LoRaWAN stack (e.g., Semtech/ST LoRaWAN v1.0.4 or v1.1), cryptographic primitives, and direct hardware interaction with the sub-GHz radio peripheral. The core can be configured as a secure enclave using hardware security mechanisms (Secure Memory Protection, Sub-GHz Radio Isolation, and PKA).
*   **Cortex-M4 (Application Processor):** Executes user business logic, complex DSP filtering on sensor streams, edge ML inferences, and non-radio peripherals.

### Inter-Processor Communication (IPC) via IPCC
Coordination between cores uses the **Inter-Processor Communication (IPCC)** peripheral combined with shared SRAM (SRAM2A/B). The ST SubGhz_Phy middleware implements a mailbox protocol:
- The Cortex-M4 issues asynchronous requests (e.g., `LMHandlerSend()`) via an IPCC channel interrupt.
- The Cortex-M0+ processes the payload, handles timing-critical channel hops and duty-cycle tracking, manages CAD (Channel Activity Detection), and fires an interrupt back to the M4 when transmission or reception windows complete.

## 2. Power Optimization: Achieving Multi-Year Battery Life

To survive 5–10 years on a single LiSOCl₂ (e.g., 3.6V ER14505) or Li-MnO₂ coin/pouch cell, average power consumption must hover in the single-digit microamps.

### Power Domain Management
The STM32WL55 provides multiple low-power modes:
1. **Run Mode:** Cortex-M4 @ 48 MHz (~5.4 mA).
2. **Stop 2 Mode:** Clocks halted, full SRAM retention, RTC running, autonomous wake-up sources active (~1.1 µA).
3. **Standby / Shutdown Mode:** Sub-300 nA, but requires cold-boot sequence.

**Rule of Thumb:** Keep the device in **Stop 2 mode** during quiescent states. 

```c
// Example: Entering Stop 2 mode on Cortex-M4
HAL_PWREx_EnterSTOP2Mode(PWR_STOPENTRY_WFI);
```

### SMPS vs. LDO
The integrated switch-mode power supply (SMPS) step-down converter drastically reduces active radio current compared to linear LDO mode:
*   At TX power +14 dBm: ~21 mA (SMPS) vs. ~39 mA (LDO).
*   Always route an external inductor (typically 10 µH) to feed the `VDDSMPS` pin unless BOM cost constraints strictly forbid inductor placement.

### Independent Core Sleeping
The Cortex-M0+ and Cortex-M4 operate with independent sleep governors. While the Cortex-M0+ waits for Class A RX1/RX2 receive windows (approx. 1s and 2s post-transmission), the Cortex-M4 can immediately enter **Stop 2**, awakening only if valid downlink data is confirmed by the M0+.

## 3. RF Front-End and Output Matching

The STM32WL55 features two distinct power amplifier (PA) outputs:
*   **RFO_LP (Low-Power PA):** Up to +14 dBm, optimized for regional limits like CE/ETSI in Europe (868 MHz).
*   **RFO_HP (High-Power PA):** Up to +22 dBm, ideal for FCC in North America (915 MHz) or long-haul rural links.

### RF Matching Topology
To avoid duplicate RF tracks, deploy a single matching network using an external RF switch (e.g., Skyworks SKY13373 or integrated dual-throw diodes) managed automatically via the internal `FE_CTRLx` (Front-End Control) signals driven by the Cortex-M0+.

*Design Note:* Keep traces strictly 50 Ω coplanar waveguide with ground. Place decoupling capacitors as close to `VBAT_RF` and `VDDA` pins as physically possible to suppress harmonics during high-power PA ramp-up.

---

## 4. Firmware Partitioning & Flashing Workflow

ST’s Dual-Core ecosystem requires managing two separate binary images:
1. **CM0+ Project:** Compiles to the high-memory region with restricted read/write access.
2. **CM4 Project:** Compiles to the low-memory flash base (`0x08000000`).

Ensure option bytes are set correctly:
*   `CBOOT2` set to 1 (enables CM0+ boot).
*   `IPCM` configured to control flash memory privilege partitions.

---

## 5. Summary Checklist for Field-Ready Nodes

| Objective | Best Practice |
| :--- | :--- |
| **Quiescent Current** | Target < 1.5 µA in Stop 2 with RTC and SRAM2 retention enabled. |
| **DC-DC Conversion** | Connect external inductor for internal SMPS step-down mode. |
| **MAC Isolation** | Restrict all LoRaWAN stack and crypto tasks exclusively to Cortex-M0+. |
| **Capacitor Sizing** | Account for LiSOCl₂ passivation: use a supercapacitor or HLC in parallel for +22 dBm bursts. |
