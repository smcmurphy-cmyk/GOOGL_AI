## Video Segments & Screen Recording Outline

### Segment 1: The Stakes of Aerospace QMS (ISO 9001 vs. AS9100D)
* **Screen Recording Target:** Split-screen side-by-side comparison matrix showing ISO 9001 baseline clauses vs. AS9100D aerospace-specific delta clauses; browser tab displaying the high-level React QMS Compliance Dashboard prototype.
* **Core Concepts:**
  * ISO 9001 sets general quality management standards (process orientation, customer satisfaction, continual improvement).
  * AS9100D incorporates all ISO 9001:2015 text verbatim while adding nearly 100 aerospace/defense-specific requirements.
  * Zero-tolerance environment: Strict emphasis on configuration management, product safety, critical items, and risk of nonconforming product escape.

### Segment 2: Clause 7.5 & 8.5.2 – Traceability & Documented Information
* **Screen Recording Target:** VS Code displaying TypeScript interface definitions representing electronic manufacturing records (PCBs, SMT components, traveler work orders) alongside a running browser view showing serial-level batch inspection.
* **Core Concepts:**
  * **Clause 7.5 (Documented Information):** Control of distribution, access, retrieval, storage, retention (often 7 to 10+ years), and revision history. Software cannot allow hard deletes or silent overwrites.
  * **Clause 8.5.2 (Identification and Traceability):** Complete chain-of-custody tracking. Every surface-mount component, integrated circuit, and passive part must trace back through its purchase order, certificate of conformance (CoC), manufacturer lot code, and assembly station.

### Segment 3: Counterfeit Part Mitigation (AS9100D Clause 8.1.4)
* **Screen Recording Target:** SMT pick-and-place inspection dashboard in React highlighting component provenance verification, vendor validation status, and Certificate of Conformance (CoC) PDF linking.
* **Core Concepts:**
  * High prevalence of grey-market and counterfeit chips in electronics manufacturing requires strict acquisition protocols from authorized distributors (e.g., Franchised/OEM-authorized).
  * Data capture requirements: CAGE code verification, moisture sensitivity level (MSL) tracking, and CoC validation before parts can be loaded onto active manufacturing feeders.

### Segment 4: Immutable Audit Trails via Microsoft SQL Server Temporal Tables
* **Screen Recording Target:** SQL Server Management Studio (SSMS) executing queries on system-versioned temporal tables; demonstrating how updates automatically generate immutable historical records.
* **Core Concepts:**
  * Why standard `updated_at` columns fail aerospace audits: Auditors demand point-in-time reconstruction of records exactly as they existed during manufacturing.
  * Utilizing MSSQL System-Versioned Temporal Tables (`PERIOD FOR SYSTEM_TIME`) to guarantee complete, tamper-resistant history without complex trigger overhead.

```sql
-- Schema: Traceable PCB Assemblies with System-Versioned History
CREATE TABLE dbo.PCBA_Assemblies
(
    AssemblyId UNIQUEIDENTIFIER NOT NULL DEFAULT NEWID() PRIMARY KEY CLUSTERED,
    SerialNumber VARCHAR(64) NOT NULL,
    WorkOrderNumber VARCHAR(32) NOT NULL,
    Revision VARCHAR(10) NOT NULL,
    InspectionStatus VARCHAR(20) NOT NULL CONSTRAINT DF_InspectionStatus DEFAULT 'PENDING',
    ValidatedByOperatorId VARCHAR(32) NOT NULL,
    SysStartTime DATETIME2(0) GENERATED ALWAYS AS ROW START HIDDEN NOT NULL,
    SysEndTime DATETIME2(0) GENERATED ALWAYS AS ROW END HIDDEN NOT NULL,
    PERIOD FOR SYSTEM_TIME (SysStartTime, SysEndTime)
)
WITH (SYSTEM_VERSIONING = ON (HISTORY_TABLE = dbo.PCBA_Assemblies_History));

-- Querying point-in-time state for an FAA/AS9100D auditor:
SELECT AssemblyId, SerialNumber, Revision, InspectionStatus, ValidatedByOperatorId
FROM dbo.PCBA_Assemblies
FOR SYSTEM_TIME AS OF '2026-03-15 14:30:00'
WHERE SerialNumber = 'SN-PCB-2026-00491';
```

### Segment 5: Enterprise Application Architecture
* **Screen Recording Target:** Architectural diagram in draw.io/Figma shifting to an active Express endpoint handling signed compliance events, validating JWT payload roles, and writing to MSSQL via strict transactional boundaries.
* **Core Concepts:**
  * **Frontend (React + TypeScript + Tailwind):** Role-gated dashboard surfaces, real-time revision banners, and non-conformance flaggers.
  * **Backend (Node.js + Express):** Strict payload validation via Zod, cryptographic signature verification for digital approvals, and audit logging middlewares.
  * **Database (MSSQL):** Enforced foreign keys, temporal history tables, and restrictive database roles preventing row mutation by standard application pools.
